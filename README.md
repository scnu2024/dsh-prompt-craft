# 提示词打磨 · dsh-prompt-craft

[English](README.en.md) | 中文

DeepSeek Harness 插件。把简短想法整理成可执行的提示词，先预览，点“应用结果”才写回输入框。

## 新的打磨流程

每次操作先分析原始意图、已有信息和当前版本，再决定提问或生成。编程、写作、学习、分析和日常任务共用这条流程。

- 短草稿也进入模型分析。信息足够时主动补充相关步骤、输出组织方式和检查方法。
- 缺少会影响结果的关键信息时，先显示最多两个问题。回答后继续，也可主动选择“按已有信息继续”。
- 具体项目事实必须来自草稿、确认回答、附件名称、实际提供的用户前文或本轮图片中清晰可见的证据。历史助手猜测和已生成版本不会成为确认事实。
- 简单任务用自然短段落，复杂任务按需使用步骤和小标题。没有固定模板或统一扩写倍率。
- 完整请求可以保持当前版本，并说明具体原因。

“再具体一点”根据尚未解决的执行缺口改写全文，保留原始需求、累计答案、最近三版文本及改进记录。没有进一步空间时按钮暂停，可通过“补充信息”继续。“再短一点”保留所有目标和明确限制。重复追加、同方向版本循环及不安全结果会被拦截，已有版本保留。

事实、限制和重复检查包含启发式规则，不能穷尽语义风险。每次最多三次模型调用，共享分析、生成和一次恢复额度；默认总超时 90 秒。格式或网络错误会明确显示。

## 安装与升级

需要 DSH `>=0.2.2-rc.1 <0.3.0`、Node `>=22`。

```sh
dsh plugin --profile desktop add dsh-prompt-craft
dsh plugin --profile web add dsh-prompt-craft
```

源码安装：

```sh
git clone https://github.com/scnu2024/dsh-prompt-craft.git
dsh plugin --profile desktop add ./dsh-prompt-craft
```

1.1.0 使用 v2 请求协议，支持输入框图片，应用成功后自动关闭预览。升级后重启 Harness 并刷新窗口，旧客户端会收到刷新提示。原有设置继续生效；旧版临时预览缓存不迁移。

## 使用

1. 输入草稿，点击右侧“打磨”。
2. 需要确认时填写问题，再继续生成；不回答也可主动按已有信息继续。
3. 查看结果、具体原因及本轮改进摘要。原文对照和高亮独立控制。
4. 使用“再短一点”“再具体一点”或“补充信息”继续完善。
5. 点击“应用结果”写回，成功后自动关闭打磨面板并清理本会话的结果缓存。插件不会发送消息。

面板支持展开阅读、明暗主题及窄窗口。重新生成时上一版仍可阅读，取消后恢复已有结果。展开时按 `Esc` 返回浮层，再按一次关闭。

应用前重新核对草稿、附件和修订号。外部编辑会重建打磨任务。附件 chip 原样保留；应用是普通编辑，可撤销。带附件的部分替换被拒绝时会停止，并提示撤销。

当前窗口的 `sessionStorage` 保存最近 20 个会话的结果、待答问题和已填答案。刷新可恢复；关闭结果清理该项。存储不可用时仍可使用。

## 输入框图片

输入框里粘贴或添加的 PNG、JPEG、WebP、GIF 图片会随打磨请求交给所选模型，分析、生成和修复均能参考。仅添加图片也能点击“打磨”；缺少任务目标时先追问。结果显示本轮参考的图片数量。普通文件继续只提供名称，历史上下文开关只读取文字。

最多 8 张图片，单张不超过 10 MiB，总计不超过 20 MiB。所选模型必须明确声明支持图片；能力未知或不可用时提示更换会话模型或打磨专用模型，不自动切换。当前已验证 `deepseek-account / deepseek-flash` 可识图。

图片变化会使旧任务失效。追问、微调和刷新后继续操作时重新读取图片；图片无法恢复时重新添加。插件的窗口缓存只保存结果和附件标识，不保存图片字节。图片通过宿主附件服务校验和存储，沿用宿主的本地附件保存策略。

## 设置

“设置 → 提示词打磨”：我的偏好、参考前面的对话、高亮改动及打磨专用模型。默认跟随当前会话模型。

偏好位于 `~/.dsh/prompt-craft/settings.json`，可用 `DSH_PROMPT_CRAFT_SETTINGS` 覆盖。

可选行配置：

```yaml
- id: prompt-craft
  name: dsh-prompt-craft
  config:
    maxDraftChars: 6000
    maxOutputChars: 12000
    maxOutputTokens: 3000
    timeoutMs: 90000
    contextMessages: 8
    contextChars: 6000
```

文字部分最多 256 KiB，带图片的请求总计最多 28 MiB，最多 64 条确认回答。达到限制时明确提示整理草稿或图片，不静默丢弃内容。

## 数据与开发

通过 DSH 宿主模型服务调用，无额外中转、遥测或外部上报。发送草稿、确认回答、附件名称、当前输入框图片、迭代记录、偏好和可选历史文字；不读取普通文件正文或历史图片。接口使用宿主鉴权通道。

零运行时依赖，无生产构建步骤。`client.js` 是浏览器模块，`index.js` 和 `lib/` 由宿主加载。接口见 [CONTRACT.md](CONTRACT.md)。

```sh
npm run check
npm test
npm run preview:ui
npm run test:ui
npm run eval:images
npm run eval:general:dev
npm run eval:general:accept
npm run eval:projects:verify
npm run eval:projects:accept
```

真实模型评测必须显式启动，普通加载和测试不会调用模型。通用评测有独立的 10 题开发集、20 题验收集，覆盖五类任务、完整请求及连续微调。验收要求短且欠明确请求的有用改进或关键追问比例至少 90%，事实编造、限制丢失和重复追加为零。语义部分采用两次顺序交换的模型评审，完整记录保留供核对。

现有技术答案题集继续作为回归；历史报告保留。最新结果见 [通用评测](eval/GENERAL-RESULTS.md)，复跑说明见 [eval/README.md](eval/README.md)。

## 限制

不读取普通文件正文，不支持流式预览；刷新会中断进行中的请求。带附件的多段编辑依赖宿主逐段接受，无法保证原子替换。图片观察依赖模型能力，模糊内容和识别错误仍需核对。
