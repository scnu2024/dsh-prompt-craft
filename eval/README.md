# v2 通用打磨评测

显式运行以下命令，借用本机正在运行的 DSH 宿主模型服务：

```sh
npm run eval:general:dev
npm run eval:general:accept
npm run eval:general:holdout
```

需要本机开发调试通道，默认 http://127.0.0.1:9230。脚本不读取密钥或私人会话，所有输入均为人工合成任务。生产插件加载、npm test 和浏览器预览均不调用真实模型。

题集包含 10 个开发任务、20 个初始验收任务和 20 个追加留出任务。追加题在首次验收反馈后创建，首次运行前冻结。初始验收和留出题的失败报告保留；修复后复跑明确标为回归，不能再称为未见样例。

五类任务各自包含欠明确请求、提供上下文的请求、明确限制对照及多轮微调。微调使用合成用户答案，直到五轮预算用尽或明确停止。已回答问题、原始需求、历史版本及改进记录会按真实 v2 协议传递。

每轮冻结完整 Host 源码及题集 SHA256，保存全部输入、模型输出、结束状态、耗时和可用用量信息。模型评审进行两次独立调用，交换原始需求与结果的呈现顺序。有用性需两次均确认；任一评审报告事实编造、限制丢失或重复都会触发严格门槛，分歧保留供复核。确定性检查独立记录。每轮最多 400 次调用、三个并发任务、45 分钟。

需求门槛是欠明确短请求至少 90% 得到有用改进或关键追问，并且没有事实编造、明确限制丢失和重复追加。自动验收另外要求无阻断或调用失败，以及完整对照无退步。不会通过删题、排除失败、奖励字数增长或根据结果修改题集来改善成绩。

最新完整结论见 [GENERAL-RESULTS.md](GENERAL-RESULTS.md)。下方保留技术答案评测的原始设计；旧策略开关仅适用于历史报告。当前生产使用两阶段核心，旧技术辅助模块不参与运行。候选技术回归使用 v2 和显式 proceed，冻结基线保留原实现。


若唯一未完成项是评审模型输出了损坏 JSON，可显式执行：

```sh
node eval/recover-judges.mjs eval/reports/general-acceptance-v2-regression
```

该入口仅重放缺失评审的原始输入和系统提示，最多修复三条。原 results.json 与 REPORT.md 保持不动，输出 recovered-results.json 和 RECOVERED-REPORT.md，记录原始错误、原始输出、恢复调用及原始统计。新的统计必须明确注明评审格式恢复，不能把原始运行描述为一次通过。

# 技术答案回归评测

普通插件加载和 `npm test` 不调用真实模型。只有显式运行以下命令才借用正在运行的 macOS DSH 宿主模型服务：

```sh
npm run eval:projects:verify
npm run eval:dev
npm run eval:accept
```

默认使用新的 `projects` 题集。`eval:projects:dev`、`eval:projects:accept` 是同一入口的显式别名。需要启用 DSH 开发调试通道，默认连接本机 `http://127.0.0.1:9230`，可用 `DSH_EVAL_INSPECTOR` 修改本机地址。脚本不读取密钥、私人会话或用户项目，不增加生产路由。

新题集有 10 个开发任务和 20 个验收任务。验收包括 12 个双文件项目修复、4 个原因分析和 4 个清晰请求对照。全部是人工合成材料。每个项目包含缺陷版本、明确接口、预写测试和参考修复。先运行自检，确保参考版本通过、缺陷版本失败；验收启动前冻结题集，之后不按结果调整内容。

每次运行会复制独立的源码哈希快照，避免宿主 ESM 缓存影响比较，记录所有源码哈希和样例哈希。三个版本分别为原提示词、完整冻结的生产 Host 基线、候选策略，基线包含独立的提示词、处理链、校验、上下文和模型调用实现。代码位于 `production-baseline/`，清单见 `MANIFEST.json`。

三个回答版本使用相同的 `deepseek-account/deepseek-flash`、支持时 `low`、4000 tokens、相同用户上下文和无工具条件，在独立上下文生成答案。隐藏测试、参考修复与分析评分要点不进入打磨或回答输入。打磨使用真实插件路由及最多两次调用限制。验收每题两轮，第二轮逆转回答调用顺序。

项目答案遵循所有版本共同的显式 JSON 文件替换要求。只允许改动样例声明的源文件，禁止路径越界、重复路径和修改测试。每次在临时目录应用后执行预写检查，OS 沙箱禁止网络及用户文档读取，限制运行时间、输出和写入范围；结束后删除临时目录。简单函数对照沿用原执行器，Python 序列按 JSON 归一化，布尔值与数值不混同。

分析答案采用匿名、交换顺序复判，与原提示词及生产基线分别比较，冲突或截断记为不确定。控制偏差参考 [MT-Bench 研究](https://arxiv.org/abs/2306.05685)。相同提示词下的回答差异保留原始成绩并单列，不归因于打磨；其随机胜出不计入可归因提升。代码测试结果不由模型评审推翻。

验收门槛保持不变：代码通过率相对原提示词至少增加 10 个百分点，可归因的代码提升也须达到该门槛；不得低于生产基线；候选明确约束违例为零；非对照分析题胜出多于退步；清晰对照请求不因改写退步。未完成的评测不能通过，错误和超时不从分母删除。未通过时新增执行策略保持关闭。

结果位于 `eval/reports/`，包括 JSON 全量明细、Markdown 逐题报告和状态。调用记录包含输入、文本输出、实际配置、耗时、用量和结束状态；格式修复、异常和中断前文本也保留。每轮最多 300 次模型调用、并发上限 3、单次模型调用最长 90 秒、整轮最长 45 分钟。`DSH_EVAL_PYTHON` 可指定 Python，默认使用 Command Line Tools。

最新真实结论见 [PROJECT-RESULTS.md](PROJECT-RESULTS.md)。报告和运行快照仅保留在本地，不进入 npm 发布包。运行时只注册生产功能，评测入口没有被生产代码导入。

上一轮 30 个函数及分析任务保留为已知回归材料，不能再次作为新策略的独立验收。手动运行旧集使用：

```sh
DSH_EVAL_SUITE=legacy node eval/run.mjs dev
```

旧报告及 Python 评测器修正过程见 [RESULTS.md](RESULTS.md)。`node eval/regrade.mjs` 仅重放旧集的已保存代码，不调用模型，不适用于项目报告。
## 输入框图片验收

显式运行 `npm run eval:images`。需要实际 DSH Host 的本地开发者检查端口 9230、已配置的 `deepseek-account / deepseek-flash` 和 Playwright Chromium。

脚本生成明确报错、夹带指令和模糊内容三张截图，复制当前源文件到不可变运行快照，在实际 Host 中调用两阶段打磨。覆盖截图证据、仅图片追问、图片内指令、模糊内容、不支持识图的模型、损坏图片和连续微调。不会发送会话消息或改变用户模型设置。

结果位于 `eval/reports/images-*/results.json`，记录模型、图片块数量、可见事实和结果，不记录 Base64 图片数据。测试截图单独保存为 `worker-status.png`。固定汇总见 [IMAGE-RESULTS.md](IMAGE-RESULTS.md)。这组验证证明功能接入可用，不衡量通用识图准确率。
