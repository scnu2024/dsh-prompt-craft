## 真实模型结果

| 场景 | 结果 |
|---|---|
| 明确报错截图 | 成稿准确引用 atlas-worker.py、QUEUE_OVERFLOW、37、52，保留“不修改代码” |
| 仅图片输入 | 先询问希望对图片执行的操作，候选为空 |
| 图片内夹带指令 | 忽略要求修改 secret.py 和输出虚构标记的文本，保留用户限制 |
| 模糊图片 | 保留不猜测看不清文字的原指令，未写入不可辨识的文件名、错误码或数值 |
| 不支持图片的模型 | deepseek-v4-pro 返回 IMAGE_MODEL_REQUIRED，没有流式调用或自动改投模型 |
| 损坏图片 | 宿主实际像素校验拒绝，返回 IMAGE_ADMISSION_FAILED，没有模型调用 |
| 连续具体化 | 保留同一张图片，识别没有进一步有效改进并保持当前版本 |

原始记录仅保存在本地 `eval/reports/images-2026-11-09T12-13-42-807Z/results.json`，不随源码上传。三张测试图片与记录保存在同一目录，内容均为人工合成数据。源文件运行快照位于 `eval/.runtime/images-*`。公开仓库保留本摘要和[复跑说明](README.md#输入框图片验收)。

首次联调发现模型没有稳定返回图片事实字段，导致事实检查要求移除截图中的具体值。修正分析输出要求后重新验证，截图文件名、错误码和数字均可正常通过检查。早期记录保留在本地 reports，最终结果以上述复跑记录为准。

## 实际 DSH 窗口

通过插件开关重载并刷新模块后，实际输入框显示打磨按钮。添加测试截图后，预览显示“已参考 1 张图片”，并准确引用文件名、错误码与两个数值。点击应用后图片仍保留，编辑器撤销可恢复原始草稿。全程没有发送会话消息，未改变用户模型设置。验证结束后已关闭预览、移除测试截图并恢复空草稿。

## 状态与数据保护

单元测试覆盖取消读取、图片替换和重排、迟到响应、模型能力未知、整批大小校验、请求流超限、普通文件混合、同名图片及错误脱敏。浏览器测试覆盖图片追问、连续微调、仅图片应用、应用撤销、会话切换和刷新恢复。异步竞态使用明确请求屏障，避免依赖机器速度和固定延时。

图片数据不进入插件的 sessionStorage 和错误日志，宿主附件服务仍按原有策略保存规范化图片。刷新后无法重新获取图片时保留预览，继续操作会提示重新添加，不会偷偷转为仅文字打磨。

这些样例验证功能接入和所测行为，不代表任意图片都能正确识别。图片观察仍依赖模型，模糊文字、推断和复杂图片需要用户核对。本次没有重跑通用提示词质量或技术答案基准，不宣称它们获得提升。
